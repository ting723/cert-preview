## 1. Architecture & Design

```text
input    bytes       → labeled DER objects (PEM scan / format sniffing)
parse   DER         → unified model (x509, keys, extensions)
verify  model + time → report (validity, chains, hostname)
format  model        → text / table / json rendering
encode  bytes        → fingerprints, PEM
```

Dependencies point strictly downward. The CLI, server, browser, and Node all build on the same `parse + verify + format` stack, so the four ports **cannot diverge**.

**Deliberately not done**: signature verification. That needs a full crypto stack (significantly bloating the WASM binary) and risks being mistaken for a "trust engine". This tool does **structural validation only** — whether subject/key identifiers line up, whether the cert is within its validity window, and whether the hostname matches a SAN.

## 2. Public API Quick Reference

| Layer | Entry point | Notes |
| --- | --- | --- |
| Input | `cert_core::input::detect(bytes)` | Sniff PEM / DER / Base64; returns `SourceFormat` and a list of DER objects |
| Parse | `cert_core::parse_bundle(bytes)` | Decode into the unified `Bundle` model |
| Verify | `cert_core::verify_report(bundle, now, hostname)` | Evaluate at `now` (Unix seconds); optional `hostname` for SAN matching; returns `Report` |
| Render | `cert_core::format::text` / `format::table` / `format::to_json` | Three renderers consuming the same `Report` |
| WASM | `view.inspect / inspectJson / inspectText / inspectTable` | The four methods called from browser / Node |
| Error | `CertViewError { code, offset, message }` | Cross-port structured error; branch on `code` |

`Report` shape (generated by ts-rs; Rust / TS fields correspond 1:1):

```ts
type Report = {
  bundle: Bundle;          // parse result (clock-independent, snapshot-comparable)
  evaluatedAt: number;     // clock used for evaluation (Unix seconds)
  certificates: CertificateStatus[]; // per-certificate verification status
};
```

## 3. Scenario-Based Guide

Each scenario below shows the **four-port equivalent**. Paths are relative to the repo root.

### Scenario A: Inspect a full certificate chain (chain.pem)

**Goal**: confirm the chain links to a self-signed root and view each level's validity.

- **CLI**: `certview fixtures/certs/chain.pem --format table`
- **Rust**: `cargo run -p cert-core --example inspect -- fixtures/certs/chain.pem`
- **Node**: `view.inspect(chain, { now })` → `report.bundle.items.length`
- **Browser**: pick "full chain chain.pem", click `inspectTable()`

Output (CLI, excerpt):

```text
│ #   │ SUBJECT                      │ ISSUER                   │ EXPIRES      │ KEY            │ STATUS       │
│ 0   │ www.example.org              │ Example Issuing CA       │ 2025-01-01   │ rsaEncryption… │ expired      │
│ 1   │ Example Issuing CA           │ Example Root CA          │ 2034-01-01   │ rsaEncryption… │ valid        │
│ 2   │ Example Root CA              │ Example Root CA          │ 2034-01-01   │ rsaEncryption… │ valid        │
```

### Scenario B: Hostname / SAN matching (rsa-leaf.pem)

**Goal**: given an access hostname (e.g. `www.example.com`), decide whether the cert covers it. This cert's SAN is `DNS:*.example.com`; a wildcard matches a single label only.

- **CLI**: `certview fixtures/certs/rsa-leaf.pem -H www.example.com --format json`
- **Node**:
  ```ts
  const m = view.inspect(rsaLeaf, { now, hostname: "www.example.com" })
                .certificates[0].hostname;
  console.log(m.matched, m.matchedName); // true, "DNS:*.example.com"
  ```
- **Browser**: fill `www.example.com` in the "hostname" box, click any render button; or pick a non-error scenario and read the `hostname` field.

Wildcard matching follows RFC 6125 §6.4.3: `*.example.com` matches `www.example.com` but **not** `a.b.example.com` (multi-level subdomain).

### Scenario C: Algorithm details (ec-leaf.pem)

**Goal**: confirm signature algorithm, public-key algorithm, and curve.

- **Node**:
  ```ts
  const it = report.bundle.items.find(i => i.kind === "certificate");
  it.signatureAlgorithm.name; // "ecdsa-with-SHA256"
  it.publicKey.algorithm.name; // "id-ecPublicKey"
  ```

### Scenario D: Private-key metadata (metadata only, no key material)

**Goal**: inspect key type and size, but **never leak the key material**. The key material is dropped at parse time and cannot be rendered.

- **CLI**: `certview fixtures/keys/rsa-2048.pkcs8.pem --format text`
- **Node**:
  ```ts
  const k = report.bundle.items.find(i => i.kind === "privateKey");
  k.format;        // "pkcs8"
  k.keySizeBits;   // 2048
  k.algorithm.name;// "rsaEncryption"
  ```

### Scenario E: Encrypted private key (rsa-2048.encrypted.pem)

**Goal**: recognize that a private key is passphrase-encrypted (this tool does not decrypt; it only flags `encrypted: true`).

- **CLI**: `certview fixtures/keys/rsa-2048.encrypted.pem --format text`
  Output shows `Encrypted: yes`.

### Scenario F: Raw DER / Base64 input

**Goal**: feed binary DER or bare Base64 (no PEM headers); the tool sniffs automatically.

- **DER**: `certview fixtures/certs/leaf.der --format text`
  Output (excerpt):
  ```text
  === Chains ===
    www.example.org   [INCOMPLETE]
      - WARNING issuer chain does not reach a self-signed root present in the bundle
  ```
  (The single cert does not carry its issuer in the bundle, so the chain is marked incomplete — exactly the value of structural validation.)
- **Node / Browser**: `view.inspect(new Uint8Array(derBytes), { now })`; text or Base64 are recognized by `detect` too.

### Scenario G: Evaluate validity at a fixed point in time (--now)

**Goal**: reproduce results with a deterministic clock (testing, auditing, comparison). `now` is Unix seconds.

- **CLI**: `certview fixtures/certs/chain.pem --now 1717200000 --format table`
  (`1717200000` = 2024-06-01; at this time the leaf is still `valid`.)
- **Node / Browser**: `view.inspect(chain, { now: 1_717_200_000 })`

> The WASM target (`wasm32-unknown-unknown`) **has no system clock**, so `now` is required; both TS loaders default it to `Date.now() / 1000` when the caller omits it, so the JS API can still be written as `view.inspect(bytes)` without error.

### Scenario H: Bad input → structured error

**Goal**: illegal input should return a `code`-branchable error, not crash.

- **CLI**: `printf 'garbage\n' | certview` → non-zero exit code, reason on stderr.
- **Node / Browser**:
  ```ts
  try {
    view.inspect(new TextEncoder().encode("this is not a certificate"), { now });
  } catch (e) {
    if (e instanceof CertViewError) {
      console.log(e.code, e.offset, e.message);
      // UNKNOWN_FORMAT  null  "input is neither PEM text nor a DER encoded structure"
    } else throw e;
  }
  ```

## 4. Per-Platform Usage

### 4.1 Command-Line CLI

The `certview` binary (from `crates/cert-cli`).

```bash
# Build
cargo build -p cert-cli

# Usage
certview [FILES...] [options]
  -f, --format <text|table|json>   render format (default text)
  -H, --hostname <HOST>             hostname to match against SAN
      --now <SECONDS>               Unix seconds for validity evaluation (default now)
  (reads from stdin when FILES omitted)
```

Examples:

```bash
# multiple files + table
certview fixtures/certs/chain.pem fixtures/certs/rsa-leaf.pem -f table

# stdin + text + hostname match
cat fixtures/certs/rsa-leaf.pem | certview --format text -H www.example.com

# fixed time + JSON
certview fixtures/certs/chain.pem --now 1717200000 -f json
```

Quick try in-repo: `cargo run -p cert-cli -- fixtures/certs/chain.pem -f table`.

### 4.2 Rust Library (server / embedded)

In `Cargo.toml`:

```toml
[dependencies]
cert-core = { path = "crates/cert-core", default-features = true }
```

Minimal usage:

```rust
use cert_core::input::detect;
use cert_core::{format, parse_bundle, verify_report};

fn inspect(bytes: &[u8]) -> cert_core::Result<()> {
    // 1) format sniff
    let detected = detect(bytes)?;
    println!("format = {:?}, objects = {}", detected.format, detected.objects.len());

    // 2) parse
    let bundle = parse_bundle(bytes)?;

    // 3) verify (now = current time; hostname optional)
    let now = std::time::SystemTime::now()
        .duration_since(std::time::UNIX_EPOCH).map(|d| d.as_secs() as i64).unwrap_or(0);
    let report = verify_report(bundle, now, Some("www.example.com"));

    // 4) render (three equivalents)
    println!("{}", format::text(&report));
    println!("{}", format::table(&report));
    println!("{}", format::to_json(&report)?);
    Ok(())
}
```

Full runnable example: `crates/cert-core/examples/inspect.rs`:

```bash
cargo run -p cert-core --example inspect -- fixtures/certs/chain.pem --hostname www.example.com
```

### 4.3 Node.js (WASM)

The WASM `nodejs` target instantiates **synchronously at import time** — no `init()` needed.

```bash
# Install tsx at the repo root (the example uses .ts-extension relative imports)
npm install tsx

# Run the example
node --import tsx examples/node/inspect.ts
# or more directly:
./node_modules/.bin/tsx examples/node/inspect.ts
```

`examples/node/inspect.ts` key excerpt:

```ts
import { readFileSync } from "node:fs";
import { load } from "cert-preview/node";
import { CertViewError } from "cert-preview/node";

const view = await load();
const chain = new Uint8Array(readFileSync("fixtures/certs/chain.pem"));

view.inspect(chain, { now: 1_717_200_000 });   // typed object
view.inspectJson(chain, { now: 1_717_200_000 }); // JSON string
view.inspectText(chain, { now: 1_717_200_000 });  // text
view.inspectTable(chain, { now: 1_717_200_000 }); // table
```

Published consumers should write `import { load, CertViewError } from "cert-preview/node"`.

### 4.4 Browser (WASM) — HTML + TS reference

This is the **standard web example**, in `examples/web/`. It references the public package `cert-preview` directly from TypeScript and covers all four methods plus the error branch.

**Prerequisite**: generate the browser WASM artifact first (after a fresh clone or pull):

```bash
npm --prefix packages/cert-preview run build:wasm:web   # generates pkg-web/
```

**Run**:

```bash
cd examples/web
npm install
npm run dev      # dev server; open the printed address
npm run build    # production build, output to examples/web/dist/
```

**`index.html` (entry)** — load the TypeScript as an ES module at the bottom:

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>cert-preview · web demo</title>
  </head>
  <body>
    <main>
      <h1>cert-preview web demo</h1>
      <textarea id="input" rows="12"></textarea>
      <button id="btn-inspect">inspect() object</button>
      <button id="btn-json">JSON</button>
      <button id="btn-text">Text</button>
      <button id="btn-table">Table</button>
      <button id="btn-error">simulate bad input</button>
      <pre id="output"></pre>
    </main>
    <!-- Key: load the TypeScript source as type="module" -->
    <script type="module" src="/src/main.ts"></script>
  </body>
</html>
```

**`src/main.ts` (referencing the public package in TS)** — the core of "how to reference from TS":

```ts
// From the public package: the browser default export is the browser loader
import { load, CertViewError } from "cert-preview";
import type { Report } from "cert-preview";

// WASM is initialized asynchronously once; every call after is synchronous
const view = await load();

const enc = new TextEncoder();

// 1) inspect object: typed Report
document.getElementById("btn-inspect")!.addEventListener("click", () => {
  const report: Report = view.inspect(enc.encode(inputEl.value), { now: 1_717_200_000 });
  output(JSON.stringify(report, null, 2));
});

// 2) JSON render
document.getElementById("btn-json")!.addEventListener("click", () => {
  output(view.inspectJson(enc.encode(inputEl.value)));
});

// 3) text render
document.getElementById("btn-text")!.addEventListener("click", () => {
  output(view.inspectText(enc.encode(inputEl.value)));
});

// 4) table render
document.getElementById("btn-table")!.addEventListener("click", () => {
  output(view.inspectTable(enc.encode(inputEl.value)));
});

// 5) error branch: structured CertViewError
document.getElementById("btn-error")!.addEventListener("click", () => {
  try {
    view.inspect(enc.encode("not a certificate"), { now: 1_717_200_000 });
  } catch (e) {
    if (e instanceof CertViewError) {
      output(`code=${e.code} offset=${e.offset} message=${e.message}`);
    } else throw e;
  }
});
```

Full file: `examples/web/src/main.ts` (with a scenario dropdown, DER binary loading, hostname input, etc.). Build is verified: `tsc` type-check + `vite build` succeed, WASM (381 KB) bundled as an asset.

### 4.5 React component example

If your front end is React, wrap `cert-preview` as a reusable component. The example is in `examples/react/`:

- `<CertViewer report={report} />` — renders a structured `Report` as cards (validity badge, SAN tags, chain completeness, diagnostics).
- `<CertPlayground />` — interactive playground (scenario dropdown, text box, hostname / now inputs, four methods + error-branch switching).

```tsx
import { load } from "cert-preview";
import type { CertViewApi } from "cert-preview";
import { CertViewer } from "./CertViewer";

export function App() {
  const [view, setView] = useState<CertViewApi | null>(null);
  useEffect(() => { load().then(setView); }, []);
  if (!view) return <p>Loading WebAssembly…</p>;
  const report = view.inspect(pemBytes, { hostname: "www.example.com" });
  return <CertViewer report={report} />;
}
```

```bash
cd examples/react && npm install && npm run dev     # http://localhost:5174/
```

## 5. Zero-build pure-browser example (importmap)

If you don't want a bundler, load the already-compiled WebAssembly with native browser ESM + `importmap`. Full runnable example: `examples/standalone/`:

```html
<script type="importmap">
  {
    "imports": {
      "cert_wasm": "/packages/cert-preview/pkg-web/cert_wasm.js"
    }
  }
</script>
<script type="module">
  import init, { inspectJson, inspect, inspectText, inspectTable } from "cert_wasm";
  await init();                       // browser target needs one async init
  const json = inspectJson(pemBytes, BigInt(Date.now() / 1000), "www.example.com");
</script>
```

Run (browsers forbid `file://` for wasm, so use a local server):

```bash
node examples/standalone/serve.mjs   # http://localhost:4321/
```

> `serve.mjs` is a minimal static server whose root is the repo root, so it can load the wasm under `pkg-web/` and read fixtures from `fixtures/`.

## 6. Build & Verification

### Prerequisites

- Rust toolchain (with `wasm32-unknown-unknown` target): `rustup target add wasm32-unknown-unknown`
- `wasm-pack`: `cargo install wasm-pack`
- Node.js ≥ 18 and npm

### Generate the WASM artifacts

```bash
npm --prefix packages/cert-preview run build:wasm:web   # browser (pkg-web/)
npm --prefix packages/cert-preview run build:wasm:node  # Node (pkg-node/)
# or both at once:
npm --prefix packages/cert-preview run build:wasm
```

> Offline: if `wasm-pack` cannot download `wasm-opt` (binaryen), set `wasm-opt = false` in `crates/cert-wasm/Cargo.toml`'s `[package.metadata.wasm-pack.profile.release]` to skip optimization — this affects size only, not correctness.

### Test & consistency

```bash
# Rust: parse / verify / render / snapshot, cross-port consistency
cargo test --workspace

# Node: smoke + "WASM output == Rust snapshot" for 21 fixtures
npm --prefix packages/cert-preview test

# Web: type-check + production build
cd examples/web && npm install && npm run build
```

**Consistency guarantee**: `crates/cert-core/tests/snapshot.rs` snapshots each fixture at a fixed clock (`2024-06-01`); `packages/cert-preview/test/consistency.test.ts` runs the same WASM in Node and asserts semantic equality with the Rust snapshots. CLI / server / browser / WASM therefore share one truth.

### Current verification results (at build time)

- Rust tests: 79 green, `cargo clippy --workspace --all-targets` zero warnings
- Node tests: 25 green (3 smoke + 21 consistency)
- Web: `tsc` type-check passes, `vite build` succeeds, WASM artifact 381 KB
